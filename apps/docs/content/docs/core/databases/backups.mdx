Dokploy provides an integrated solution for backing up your databases, ensuring data safety and recovery capabilities.

Scheduled backups are available for **Postgres**, **MySQL**, **MariaDB**, **MongoDB** and **libSQL**. Redis does not have database backups.

## Backing Up Your Database

To configure database backups, navigate to the `Backups` tab of your database. Here's what you'll need to set up:

- **Destination**: Specify where your backups will be stored. Buckets can be configured in the `/dashboard/settings/destinations` route.
- **Database**: Enter the name of the database you want to backup.
- **Schedule**: Define the schedule for your backups using cron syntax.
- **Prefix Destination**: Choose a path under which backups will be stored in your bucket.
- **Custom File Name** (optional): A name that is prepended to the automatically generated timestamp of each backup file.
- **Keep the latest** (optional): Only keeps the latest N backups in the destination. If left empty, all backups are kept.
- **Enabled**: Toggle whether backups are active. The default setting is enabled.

## Backing Up Databases in Docker Compose

Databases that run inside a Docker Compose service can be backed up from the `Backups` tab of the compose. In addition to the fields above, you need to set:

- **Database Type**: PostgreSQL, MariaDB, MySQL or MongoDB.
- **Service Name**: The service of your compose file that runs the database.

### Testing Your Backup Configuration

To ensure your backup settings are correctly configured:

1. Click the `Run Manual Backup` button (play icon) next to the backup.
2. This will initiate a backup to the S3 bucket you selected.
3. Check the bucket to see the result of the backup.

This feature provides peace of mind by verifying that your backup process is set up correctly before relying on it for operational backups.

To restore a backup, see [Restore](/docs/core/databases/restore).
