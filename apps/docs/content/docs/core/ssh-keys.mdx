Dokploy provides a section exclusively for SSH keys, allowing you to manage your SSH keys in a centralized location.

SSH Keys can be used for two purposes:

- **Private Repositories**: You can use SSH Keys, to access to private repositories, this is only for `Git` provider
in your application or docker compose.
- **Multi Server**: You can use SSH Keys, to access remotely to your servers via SSH.

To create a SSH Key, is a very easy process, just click on `Create SSH Key`

We offer two SSH Keys Generation types:

1. **RSA Key**: This is the most commonly used key type, and generates a 2048-bit RSA key.
2. **Ed25519 Key**: This is a newer key type that generates a 256-bit Ed25519 key.

<Callout>
    You can also create or paste your own SSH Key, you can edit the `Private Key` and `Public Key` fields without restrictions,
    make sure to use the correct format for the key type you are using.
</Callout>

Once a key is created, only its **name** and **description** can be edited. To change the key itself, create a new SSH key.

Only **owners** and **admins** can view or download the `Private Key` of an existing key. Other members see it empty.

## Encryption at Rest

Private keys are encrypted with AES-256-GCM before they are stored in the database, the same way as environment variables. They are decrypted only when Dokploy needs them (connecting to a server, cloning a repository, etc.).

The encryption key comes from the `ENCRYPTION_KEY` environment variable if it is set, and from `BETTER_AUTH_SECRET` otherwise.

<Callout type='warn'>
    Keep that secret stable and back it up. If it changes or is lost, for example when you restore the database on a new server without it, or roll back to a Dokploy version older than this feature, encrypted private keys can't be decrypted and stop working. Create the affected keys again in that case.
</Callout>

<Callout>
    SSH keys created before this change are stored in plaintext and keep working as they are. They are not migrated automatically. To encrypt one, create it again.
</Callout>
