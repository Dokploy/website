## What are DNS Providers?

DNS Providers let you connect Dokploy to your DNS host so you can browse your zones and create the record a domain needs, instead of switching to your DNS provider's dashboard by hand.

<Callout type="info">
  DNS Providers are available to owners and admins on every plan. Managing them is covered by the `dnsProvider` permission resource, which an Enterprise [custom role](/docs/core/enterprise/custom-roles) can grant granularly.
</Callout>

Supported providers:

- [Cloudflare](/docs/core/dns-providers/cloudflare)
- [AWS Route53](/docs/core/dns-providers/route53)
- [Porkbun](/docs/core/dns-providers/porkbun)
- [Infomaniak](/docs/core/dns-providers/infomaniak)
- [OVHcloud](/docs/core/dns-providers/ovh) (also Kimsufi and So you Start)

## Creating a Provider

Go to **Settings → DNS Providers** and click to add a provider. Pick the provider, give it a name, and fill in the credentials — see the provider pages for exact steps. Use **Test Connection** to validate the credentials before saving.

Credentials are masked in the UI after saving; leaving a masked field untouched on an edit keeps the stored value. The provider type is locked once created — to switch providers, create a new one.

## Managing Records

From the provider list, click **View Domains** to open the zones your credentials can see. Click a zone to expand its records:

- Records of type **A**, **AAAA**, **CNAME**, **MX**, **TXT**, **NS**, **SRV**, **CAA** and **PTR** are editable and deletable from Dokploy.
- Any other record type returned by the provider is listed read-only.

To add a record, click **Add Record** and fill in:

- **Type**: one of the editable record types above.
- **Name**: the hostname, e.g. `app.example.com`. Use `@` for the zone's root/apex domain.
- **Content**: the label changes with the type — **IPv4 address** for A, **IPv6 address** for AAAA, **Target** for CNAME, **Mail server** for MX, and so on. MX, SRV and CAA values are written in one field, priority first (for example `10 mail.example.com`). For A records, an optional **Fill from server** dropdown auto-fills the value with the IP of a server registered in Dokploy.
- **Proxied** (Cloudflare only): available on A, AAAA and CNAME records. Proxied records always use automatic TTL.
- **TTL** (optional): leave empty for the provider's automatic/default TTL.

**Add Record** never replaces a record with different content. If a record with the same type and name already exists but points somewhere else, the new one is added next to it, for example a second TXT record for a site verification next to your SPF record. (A name can only have one CNAME record, so the provider rejects a second one.) If a record with the same type, name and content already exists, it is updated instead of duplicated. To change the value of an existing record, edit that record.

<Callout type="warn">
  Deleting a record from this screen removes it from the actual DNS provider, not just from Dokploy — the confirmation dialog calls this out explicitly.
</Callout>

## Relationship to Domains

DNS Providers is a standalone integration under **Settings**. It is not (yet) wired into the "add domain" flow on applications or Compose services — creating a domain there still expects the DNS record to already point at your server. Use DNS Providers to create that record first (or in parallel), then add the domain in the service as usual.

## Access Control

Managing DNS providers is covered by the `dnsProvider` permission resource:

- **Owners and admins** can create, update, delete and test providers, and manage records.
- **Members** have no access to DNS providers.
- With an enterprise license, **custom roles** can grant each action (`read`, `create`, `update`, `delete`) granularly. Creating and editing records requires `update`; deleting a record requires `delete`.

Every create, update and delete on a DNS provider is recorded in the [Audit Log](/docs/core/enterprise/audit-logs).
